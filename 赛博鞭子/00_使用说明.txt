赛博鞭子 · 内网便携版 v1.0.1
============================

v1.0.1 更新与安装
-----------------
修复 Chrome 页面绑定后鞭子置顶不可靠的问题：创建时设置原生 TOPMOST 样式，
在显示和每次绘制后明确恢复 HWND_TOPMOST 层级，同时禁止激活鞭子窗口。
输入焦点保留在模型网页 / 终端；不要求管理员权限。

交互改为：左键点击抽一下，右键立即收起，Esc 立即收起。
移动鼠标只控制鞭子动画，不再自动响鞭或发送催促。模型发送冷却继续保留。

升级先从旧版托盘菜单选择“退出”，解压此包，再双击 START.cmd。
本版自动在 bin\v1.0.1 生成新 EXE，不复用 bin\v1.0 中的旧 EXE。
原来的模型地址、密钥、催促语等设置继续沿用，无需删除设置目录。
绑定关系需要按 Alt+Shift+B 重新绑定；设置页标题应显示 v1.0.1。


一、先跑起来（无需模型地址，也能体验动画）

1. 完整解压 ZIP。不要在压缩软件内部直接运行。
2. 普通双击 START.cmd，不需要“以管理员身份运行”。
3. 第一次会用 Windows 自带的 .NET Framework C# 编译器生成程序。
   通常等待数秒。此过程不联网，不安装软件，不修改 PowerShell 执行策略。
4. 首次运行会显示设置页。选“仅动画和音效”，点击“保存并召唤”。
5. 移动鼠标控制鞭子惯性动画；左键每点一次抽一下并播放随机音效。
   右键立即取消 / 收起；Esc 也可以立即收起。移动速度不再触发催促。
6. 设置关闭后程序留在右下角托盘，可能位于“隐藏图标”中。
   托盘左击召唤 / 收鞭，右击可打开设置或退出。

适用目标：Windows 10 / 11、带桌面的 Windows Server 2019 / 2022。
前提是系统已具备 .NET Framework 4.5 或更高版本及自带 csc.exe。
这是依赖系统组件的免安装包，不是一个完全脱离 Windows 运行时的原生 EXE。
无需额外安装 Python、Node.js、Electron、npm、SDK 或第三方 DLL。
如果单位镜像删除了 .NET 编译组件，脚本会提示缺失并停止，不会自动下载。

二、配合内网 Dify / 模型网页

1. 设置中选择“网页聊天”。
2. 如需抽鞭后直接发送，勾选“文字填入后自动按 Enter”。
   默认关闭时，只填入催促语，由你手动发送。
3. 切换到模型网页，点进聊天输入框，再按 Alt+Shift+B 绑定窗口。
   也可点托盘菜单的“3 秒后绑定模型窗口”，然后在 3 秒内完成切换。
4. 保持聊天输入框焦点，按 Alt+Shift+W 召唤；左键点击抽鞭并催促。
5. 中文催促语随机填入，每次发送之间有冷却时间，默认 2.5 秒。

网页模式不发送 Ctrl+C，不读取屏幕，不读取网页内容，不调用模型 API。
它只向绑定且位于前台的窗口发送模拟按键。焦点变化时取消后续按键。
绑定以 Windows 窗口为单位，不识别浏览器标签页，也不能识别网页输入框。
因此切换标签页后请确认仍是模型页面，并重新点进输入框。
它不清空输入框已有文字；需要发送新问题时先完成自己的输入。
网页正在生成答案时能否收到催促语，取决于网页是否允许输入和发送。
若网页把 Enter 用于换行，请关闭自动 Enter，并自行点击网页发送按钮。
如果目标窗口使用了管理员权限，普通用户程序可能无法向它发送按键。

三、配合终端里的模型助手

1. 设置中选择“终端助手”，绑定正在运行助手的终端窗口。
2. 如需接近 OpenWhip 原版行为，勾选：
   - 终端模式：先发送 Ctrl+C，再填入催促语。
   - 文字填入后自动按 Enter。
3. 抽鞭后先发送 Ctrl+C，等待 350 毫秒，填入随机催促语并发送。

终端选项仅用于已经运行中的交互式模型助手。普通 shell 命令行会把
催促语作为命令解释，因此应先确认终端当前处于助手的交互输入状态。
如果中文按键在某种终端中不生效，选“剪贴板粘贴”。此方式临时使用
剪贴板，并在约 0.9 秒后尽量恢复原内容；如你已复制新内容则保留新内容。
默认 Unicode 方式不占用剪贴板。

四、直接接入内网 vLLM / OpenAI 兼容接口

1. 设置中选择“内网 API 聊天”，进入“内网 API”页。
2. API 地址示例：
   直连 vLLM：http://你的内网IP:8100/v1
   Nginx 路由：http://你的内网IP:11434/vl2b/v1
   也可填写完整的 .../v1/chat/completions 地址。
3. 模型名填写 vLLM 启动时 --served-model-name 后面的值。
   如果未设置别名，请按服务对外提供的实际模型名称填写。
4. 密钥按内网服务配置填写；无认证则留空。
   如果沿用 --api-key dify-local，则密钥填写 dify-local。
5. 点击“保存并测试连接”，程序会向所填内网接口发一条简短测试问题。
6. 在聊天面板输入任务，Enter 发送；Shift+Enter 换行。
7. Alt+Shift+W 召唤，左键点击催促，右键收起鞭子。

支持 OpenAI 兼容 chat/completions 的流式文字回答和普通 JSON 回答。
只支持文字聊天；bge-m3 等向量接口不是该聊天接口。
Dify 的普通网页可用“网页聊天”；本版未实现 Dify 专有 API 协议。
API 模式不向当前前台窗口发送模拟按键，也不需要绑定外部窗口。

“API 回答中抽鞭”选项开启时，会取消当前客户端请求，保留已显示的
部分回答，追加催促语，再发送新请求。服务端是否立即停止原计算，
取决于推理服务对断开连接的处理。关闭此选项时，回答中抽鞭只响音效。
取消和重发并不会提高 GPU 的实际推理速度。

聊天内容仅在本次运行的内存中保留，不自动保存为文件。
请求发送系统提示词、首条问题及最多最近 24 条消息，保留当前任务上下文。
关闭聊天窗口只隐藏窗口；点击“停止回答”或退出程序才停止客户端请求。
清空对话会同时停止当前客户端请求。

五、纯内网约束

动画、音效、托盘、窗口绑定和网页 / 终端模式完全在本机工作。
API 模式仅在主动发送 / 测试 / 催促时请求配置的接口。
仅接受 localhost、127.x、10.x、172.16–31.x、192.168.x、IPv6 ULA，
或解析结果全部属于这些范围的主机名。公网地址会被拒绝。
建议直接填写内网 IP，减少 DNS 解析问题。
不使用系统代理，不跟随 HTTP 跳转，不发送统计数据，不检查更新。
HTTPS 使用 TLS 1.2 和系统证书验证，不绕过证书错误。
如使用企业自签证书，请使用已受系统信任的证书链或现有内网 HTTP 入口。
源代码和程序没有调用云端模型或 CDN；启动脚本没有任何下载步骤。

六、快捷键和设置

Alt+Shift+W：召唤 / 收鞭。
Alt+Shift+Q：手动抽一下（可用于测试音效和发送）。
Alt+Shift+B：绑定当前前台模型窗口。
Esc：鞭子显示期间立即收起。
左键按下：抽一下（按住不会自动重复）。
右键按下：立即取消 / 收起鞭子。
鞭子显示时左右键的按下和抬起都由鞭子接收，不传给底下的网页。

快捷键被其他程序占用时，会提示并保留托盘菜单操作。
移动鼠标仅驱动惯性动画，不再通过速度触发音效或模型催促。
鞭子大小支持 70%–220%，可适配不同屏幕和缩放。
物理更新目标 60 Hz，实际绘制帧率取决于 Windows 定时器和机器负载。
闲置在托盘时停止动画计时器，仅保留快捷键和托盘消息处理。
发送冷却仅限制模型催促，不限制正常的音效体验。
“催促语”页每行一条，可直接替换为自己的中文或英文句子。

七、共享盘、程序位置和升级

START.cmd 使用绝对源路径，在本地用户目录生成 EXE，不切换到共享盘。
兼容桌面被重定向为 \\服务器\共享\用户\Desktop 的 UNC 路径。
CMD 初始可能提示 UNC 不能用作当前目录；此提示不会影响后续绝对路径操作。

生成位置：%LOCALAPPDATA%\CyberWhip\bin\v1.0.1\CyberWhip.exe
设置位置：%LOCALAPPDATA%\CyberWhip\settings.json
构建日志：%LOCALAPPDATA%\CyberWhip\bin\v1.0.1\build.log
异常日志：%LOCALAPPDATA%\CyberWhip\error.log
程序只写当前用户可写目录，不创建系统服务，不设置开机启动。
API 密钥采用当前 Windows 用户的 DPAPI 加密保存。
换电脑 / 换 Windows 用户后，需要重新填写密钥。

普通启动复用已生成的 EXE。要重新生成：先从托盘退出，再双击 BUILD.cmd。
BUILD.cmd 构建完成后会显示 EXE 位置；然后可双击 START.cmd 或生成的 EXE。
生成的 EXE 已嵌入五种 WAV 音效，不需要旁边再放音效文件。
保留 EXE 同目录的 CyberWhip.exe.config 即可使用系统运行时运行。
删除生成目录即可移除程序；如需一并清掉设置，退出后删除 CyberWhip 用户目录。

八、检查和问题定位

CHECK.cmd：利用系统编译器编译并执行本地检查，不发网络请求。
检查包括 INPUT 结构尺寸、私网 IP 边界、接口路径、流式 / 普通 JSON
中文回答、设置边界、API 密钥加密、甩鞭 / 掉落物理逻辑，
以及透明窗口恢复原生置顶层级并保留前台键盘焦点。
置顶检查会短暂打开临时测试窗，不绑定或操作你的真实模型窗口。
检查日志：%LOCALAPPDATA%\CyberWhip\bin\v1.0.1\check.log
检查编译日志：同目录 check_build.log

如果双击后没有设置窗口：先检查隐藏托盘图标，再查看 build.log / error.log。
如果生成失败：把 build.log 内容发回，保留实际报错行，不必安装开发环境。
HTTP 401/403：检查密钥和接口权限；404：检查 Nginx 路由及 v1 路径。
HTTP 400：检查模型名、上下文长度和最大输出 token；等待失败：检查端口和服务。

当前交付环境为 Linux。源码词法结构、启动脚本静态检查、资源格式和 ZIP
完整性已检查；未在当前环境编译或运行 Windows EXE，也未测试公司真实接口。
CHECK.cmd 是供 Windows 本机执行的检查，不代表交付前已执行的 Windows 实测。

九、与原项目的关系

根据你提供的 OpenWhip-main.zip 参考交互和绳索物理重新实现。
原版用 Electron + koffi；本版用 Windows 自带 .NET Framework / Win32。
保留类似的白边黑色鞭身、惯性弯曲、随机响鞭与托盘召唤，
采用左键抽鞭、右键取消，增加中文催促语、绑定窗口、发送冷却和可选内网 API 聊天。
音效由所附原项目五个 MP3 转为 WAV，以便使用系统音频组件。
源项目信息见 THIRD_PARTY_NOTICES.txt；本版完整源码位于 src。
